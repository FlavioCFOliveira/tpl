# tpl v0.1.0 — SQLite and MySQL providers

- **Version:** 0.1.0
- **Date:** 2026-11-05
- **Tag:** `v0.1.0`

`tpl` reads the schema of a database and renders it through MiniJinja templates
loaded from disk at render time. Until this release it read MariaDB only. This
release adds **SQLite** and **MySQL** as database providers, reports connection
and login failures by the phase and the error number that caused them, hardens
the rewrite of `.tpl/.cfg` and the escaping of terminal output, and cuts the
heap a cached render of a large database holds to about half.

Under the project's pre-1.0 versioning rule, new functionality and any breaking
change move the minor number; this release therefore moves from `0.0.2` to
`0.1.0`. Some exit codes change for login errors: see
[Exit codes and messages that changed](#exit-codes-and-messages-that-changed).

## Highlights

- **SQLite as a database provider.** A database entry with
  `provider = "sqlite"` names a database file in the new `path` key. The eight
  `schema` subcommands, `tpl cache load`, `tpl render` and
  `tpl cfg database test` read it through the SQLite library built into `tpl`,
  opened read-only, never created, and hardened as untrusted input.
- **MySQL as a database provider.** A database entry with `provider = "mysql"`
  reads a MySQL server, with the same connection keys as a `mariadb` entry, in a
  session set read-only and confirmed by reading it back. The supported series
  are MySQL's LTS series under Oracle Premier or Extended Support: `8.4` and
  `9.7` in this release, and no Innovation release.
- **`database.provider` in every document.** The JSON documents and the render
  context name the provider — `mariadb`, `mysql` or `sqlite` — and
  `tpl schema info` prints it in a `provider` row. `schema_version` and
  `cache_format` stay at `1`.
- **Connection failures name their phase and cause.** A failed TCP connect, TLS
  handshake, login, version probe or catalogue query is reported against the
  phase it reached, with a `cause` and a `hint` for that phase; `-v` writes one
  `phase:` line per connection phase and session statement.
- **Safer `.tpl/.cfg` rewrites.** A rewrite acts only inside the `.tpl` folder
  the trust checks judged, follows no link, and is `fsync`ed so that a power loss
  leaves the previous file or the new one, whole.
- **Cached renders of large databases.** A cached `tpl render` holds about half
  the heap it held, and a whole-database render passes from the cache up to
  about 4 600 tables under the default `core.render_memory_limit`.

## Exit codes and messages that changed

These changes alter what a caller observes on the three channels `tpl`
publishes: the exit code, `stdout` and `stderr`. A script or an agent that
branches on them should be checked against this list.

- **Login error packets are classified by their number.** `1045` and `1698`
  keep exit `77`. `1130`, `1862`, `4151` and `4150` (`3118` and `3955` for a
  `mysql` entry) keep `77` and now carry a `cause` and a `hint` for the reason.
  **`3159` now exits `78`**, where it exited `77`. **`1040`, `1203`, `1226` and
  `1129` now exit `69`**, where they exited `77`, and so does every other
  number, and `1044` or `1049` on a connection that names no database. **`1102`
  now exits `78`** on a connection naming a database.
- **`tpl cfg database test` reads only a privilege error as
  `can_read_catalogue: false`.** An error packet carrying `1044`, `1142`, `1143`
  or `1227` still answers `false` with exit `0`. Any other error packet now exits
  `69`, naming the error number, and writes no document.
- **A short or malformed packet from a server exits `69`**, where it ended
  `tpl` with `70`.
- **Error messages of connection failures are reworded.** A login that does not
  complete, a failed version probe or catalogue query, a failed TCP connect
  other than a refusal, a failed TLS handshake and an expired
  `core.connect_timeout` or `core.query_timeout` each carry a new `error` line,
  `cause` and `hint`. Their exit code, `69`, is unchanged. A refused TCP
  connect, `ECONNREFUSED`, keeps its message word for word.
- **`-v` output.** The TCP connect's `phase:` line no longer carries the time of
  the TLS handshake and the login, and the session statements are reported as
  `phase:` lines instead of `server query`. The `query:` lines are unchanged.
- **Escaped output.** C1 controls (U+0080 to U+009F) and the twelve Unicode
  `Bidi_Control` characters are now escaped in text output and in every
  diagnostic as `\u{…}`, and in JSON output as `\u` and four hexadecimal
  digits.

## Changes by area

The full list is the `0.1.0` entry of
[`CHANGELOG.md`](https://github.com/FlavioCFOliveira/tpl/blob/v0.1.0/CHANGELOG.md).

### SQLite provider

- An entry's `provider` key is `mariadb` (the default when the key is absent),
  `mysql` or `sqlite`; a `sqlite` entry names its file in `path`, read literally
  and resolved against the directory that holds `.tpl`.
- `--provider` and `--path` on `tpl cfg database add` and `update`, and the keys
  `database.<name>.provider` and `database.<name>.path` for `tpl cfg set`, `get`
  and `unset`. An incoherent combination exits `64` and writes nothing.
- SQLite has no routines: `routines` is always `[]`, and a routine named on the
  command line exits `66`.
- Exit codes of a `sqlite` entry: `74` when the file is missing or cannot be
  opened or read; `78` when the path is not a regular file, the file is not a
  SQLite database, is damaged or holds a schema `tpl` refuses, the entry lacks
  `path` or carries a key its provider does not take, or the file holds names
  that differ only in bytes that are not valid UTF-8; `69` when a writer keeps
  the database locked past `core.query_timeout`; `70` when a safeguard of the
  read does not take effect.
- A read of a database in write-ahead-log mode may create `<file>-wal` and
  `<file>-shm` beside it — the only files a read writes outside `.tpl`.
- In templates, the `numeric` test is true for the `data_type` values
  `integer`, `numeric` and `real`, and `primary_key` and `unique` answer from
  the table's `primary_key`, so a SQLite rowid key satisfies both. No answer
  over a MariaDB document changes.

### MySQL provider

- `--provider mysql` on `tpl cfg database add` and `update`, with the flags of a
  `mariadb` entry; the entry refuses `path`, and neither DSN scheme selects the
  provider.
- The catalogue is read from twelve `INFORMATION_SCHEMA` tables, in a session
  set read-only and confirmed by reading `@@session.transaction_read_only` back.
- Exit `78` when the server is not MySQL (a MariaDB server included), when its
  series is older than the newest supported one and not supported (such as
  `8.0`), when the session cannot be made read-only, and when a login over an
  unencrypted session needs the server's RSA public key, which `tpl` never
  requests. A series newer than every supported one is read and marked
  `newer_than_supported`, at exit `0`.
- A `CHECK` constraint's `level` and a view's `algorithm` are `null`. The
  `data_type` values `json`, `geomcollection` and `vector` are decomposed like
  any other type; `json` satisfies the `textual` test. Expressions are carried
  with one layer of MySQL's backslash escaping removed. An index with a
  functional key part is not carried.
- An entry with an empty or absent password logs in to a MySQL account that has
  no password, as MySQL's own client does.

### Connections and diagnostics

- Login error packets, failed TCP connects, failed TLS handshakes, failures on an
  open session and expired deadlines are reported as listed in
  [Exit codes and messages that changed](#exit-codes-and-messages-that-changed).
- `core.connect_timeout` bounds DNS resolution, the TCP connect, the TLS
  handshake and the login, and an expiry names the phase it reached.
- The read-only session statement, its read-back and the version probe each have
  their own deadline of `core.query_timeout`.

### Cache and render

- A cached `tpl render` reads a table's `foreign_keys` and `referenced_by` only
  when the template first reaches them; a damaged part is a cache miss only
  where the template reaches it.
- A read served from the cache needs no credential: `${VAR}` expansion and
  `password_command` run only in an invocation that opens a connection.

### Help text

- `tpl help cfg database add` and `update` document `--provider` and `--path`,
  with a SQLite example; `tpl help cfg set` lists the two new keys;
  `tpl help cfg database test` states what its answers mean for a `sqlite`
  entry and names which server answered.
- The exit codes of the `schema` subcommands, `tpl render`, `tpl cache load` and
  `tpl cfg database test` name the conditions of a `sqlite` entry, and the `78`
  of every command that connects names a server that is not a supported version
  of the entry's provider.
- `tpl render --help` and the `context_variables` of `tpl help --format json`
  list `provider` in the `database` variable.

### Fixes

- A cached render of a large database holds about half the heap it held.
- A NUL character in a `host`, `user`, `password`, `database`, a `dsn` part, a
  `sqlite` `path` or a `password_command` output is refused (`78` in
  `.tpl/.cfg`, `64` on the command line), where it was cut at the NUL.
- An include suggestion never names the template that holds the include, and a
  name that is a FIFO, a socket or a device gets no suggestion.
- A `mariadb` entry with an empty password logs in to an account that has no
  password, where it was refused with `77`.

### Security

- `.tpl/.cfg` rewrites act relative to the `.tpl` folder the ownership and mode
  checks opened and held, follow no link, and are durable; a failure after the
  rename exits `74` with
  `error: .tpl/.cfg was written, and its durability could not be confirmed`.
- C1 controls and bidirectional formatting characters are escaped, for every
  provider.
- Dependencies moved to `rustls` 0.23.46, `rustls-webpki` 0.103.16,
  `webpki-roots` 1.0.10 and `tokio` 1.53.3, which close RUSTSEC-2026-0346,
  RUSTSEC-2026-0347, RUSTSEC-2026-0348, RUSTSEC-2026-0349, RUSTSEC-2026-0381,
  RUSTSEC-2026-0382 and RUSTSEC-2026-0386.

### Library API

`tpl::Error` gained variants for the SQLite and MySQL providers and for the
classification of connection failures; `tpl::model` gained
`database::Provider`, `index::PrimaryKey` and `Database::provider`;
`Table::primary_key` now returns a `PrimaryKey`; and fields a SQLite or MySQL
read cannot fill became `Option`. The library carries no stability promise
(`DIV-032`): the contract is the command line and the JSON document.

## Upgrade from v0.0.2

1. **Existing projects need no change.** An entry without a `provider` key is a
   `mariadb` entry, and a `--context` document without `database.provider` is
   read as `mariadb`.
2. **Check scripts and agents that branch on login exit codes.** Error `3159`
   now exits `78`, and `1040`, `1203`, `1226`, `1129` and unclassified numbers
   now exit `69`, where they exited `77`. `tpl cfg database test` exits `69` for
   an error packet that is not a privilege error.
3. **Check tooling that parses `-v` output or diagnostic text**, which changed
   as listed above.
4. **Add a SQLite or MySQL entry** with
   `tpl cfg database add <name> --provider sqlite --path <file>` or
   `tpl cfg database add <name> --provider mysql --host <host> --schema <database>`.

## Installation

```sh
curl -fsSL https://raw.githubusercontent.com/FlavioCFOliveira/tpl/main/install.sh | sh
```

The same command installs and updates `tpl`, into `/usr/local/bin` by default,
or into the directory `TPL_INSTALL_DIR` names. To install or update the Claude
Code skill:

```sh
curl -fsSL https://raw.githubusercontent.com/FlavioCFOliveira/tpl/main/install-skill.sh | sh
```

The release carries one archive per supported target
(`x86_64-unknown-linux-musl`, `aarch64-unknown-linux-musl`,
`x86_64-apple-darwin`, `aarch64-apple-darwin`), the skill archive
`tpl-skill-v0.1.0.tar.gz`, and one `SHA256SUMS` file covering all five
archives. **The archives are not signed.**

## Test evidence

The mandatory validation pipeline was run locally on the release candidate:
`develop` at `7d7aaa4` with the version bumped to `0.1.0`.

| Command | Result |
|---|---|
| `cargo fmt --all -- --check` | exit 0 |
| `cargo clippy --all-targets --all-features -- -D warnings` | exit 0, no warning in `tpl` |
| `cargo build --release` | exit 0; the binary prints `tpl 0.1.0` |
| `cargo test --all-features` | exit 0: 1 679 passed, 0 failed, 13 ignored |
| `cargo audit` | exit 0: 154 dependencies scanned, no advisory reported |

The 1 679 tests are 1 246 unit tests, 431 integration tests in 20 suites, and
2 doc-tests.

- **Database fixtures running.** The MariaDB fixture (series 10.11, 11.4, 11.8
  and 12.3, and a server without TLS) and the MySQL fixture (series 8.4 and 9.7,
  each with and without TLS, and an 8.0 server for the refused-series case) were
  started and stopped through their harnesses, so the tests that need a real
  server ran against them.
- **Assertions skipped on this target.** 2 tests skipped their assertion and are
  counted in the passed total: both observe a syscall trace that exists only on
  the two Linux targets.
- **Measurement tests ignored.** 13 tests are marked `#[ignore]` because they
  depend on wall-clock timing or on memory sampling. `cargo test` does not run
  them.
- **Environment:** `aarch64-apple-darwin`, macOS 27.2, rustc 1.99.1.
- **At the tag:** the release workflow re-runs the same five commands on all
  four supported targets before it publishes anything.
