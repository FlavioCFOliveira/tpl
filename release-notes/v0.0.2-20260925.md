# tpl v0.0.2 — agent skill, help banner and hardening

- **Version:** 0.0.2
- **Date:** 2026-09-25
- **Tag:** `v0.0.2`

`tpl` reads the schema of a MariaDB database from `INFORMATION_SCHEMA` and
renders it through MiniJinja templates loaded from disk at render time. This
release adds a Claude Code skill that operates `tpl`, hardens the cache and the
filesystem paths `tpl` reads and writes, tightens configuration validation, and
contains **one breaking change** to the template surface.

## Highlights

- **A Claude Code skill.** `skill/` lets Claude Code agents operate `tpl` through
  the `tpl` binary. Each release now carries `tpl-skill-v0.0.2.tar.gz`, and
  `install-skill.sh` installs or updates it in one command.
- **A help banner.** Every text help opens with
  `tpl v<version> - Code Generation based on database schema`.
- **Configuration validation.** `tpl cfg set core.database` refuses an entry the
  file does not declare, and `.tpl/.cfg` must be a regular file.
- **Cache and filesystem hardening.** No cache path is read, written or removed
  through a symbolic link, cache paths are resolved relative to directories
  already opened, and a template or `.cfg` that is a FIFO no longer makes `tpl`
  block.
- **Render changes, one of them breaking.** The lookup functions are renamed,
  and `tpl render --context` refuses a document of another `schema_version`.
- **On-demand release process.** Pushing a tag no longer publishes a release;
  the release workflow is started by hand against the tag.

## Breaking changes

- **The lookup functions are renamed.** In the registered template surface,
  `table(name)`, `view(name)` and `routine(name)` are now `table_named(name)`,
  `view_named(name)` and `routine_named(name)`. `column` is unchanged. A template
  that calls an old name fails with exit code `65`.

  **This release is an exception to the project's pre-1.0 rule**, under which
  a breaking change moves the minor number. The maintainer released this
  breaking change in `0.0.2`, a patch-level version number, by decision; the
  rule itself is unchanged.

## Changes by area

The full list is the `0.0.2` entry of
[`CHANGELOG.md`](https://github.com/FlavioCFOliveira/tpl/blob/v0.0.2/CHANGELOG.md).

### Added

- The Claude Code skill in `skill/`, with `skill/scripts/check-coverage.sh`,
  which checks the skill's command map against `tpl help --format json`.
- The skill release asset, `tpl-skill-<tag>.tar.gz`, listed in `SHA256SUMS`, and
  the installer `install-skill.sh`.
- `tpl::run_from(args)` in the library, which runs `tpl` on an explicit argument
  vector so a fuzz harness can drive it in process. The library API carries no
  stability promise.

### Changed

- The release workflow runs only when started with
  `gh workflow run release.yml --ref vX.Y.Z`, and refuses a ref that is not a
  tag.
- The help banner on every text help. `tpl help --format json` and
  `tpl version` are unchanged.
- `tpl cfg set core.database` requires the entry to exist (exit `66`, with a
  nearest-match `hint`).
- `tpl cfg unset` of an absent block suggests the nearest block.
- The lookup functions are renamed (see [Breaking changes](#breaking-changes)).
- `.tpl/.cfg` must be a regular file; a symbolic link, directory, FIFO, socket
  or device is refused with `78`.

### Fixed

- A template that is not a regular file is never opened.
- Cache operations do not follow a `.tpl/.cache` swapped for a link during the
  operation.
- `tpl cache clean`, the `schema` subcommands, `tpl render`, `tpl cache load`
  and `tpl cache status` refuse a linked cache folder with `78`.
- A partial `tpl cache clean` keeps `loaded_at`.
- `tpl cache status` no longer reports a cache holding objects as empty when
  `meta.json` is absent or unusable.
- `table`, `view` and `routine` are undefined in a render given no `--table`,
  `--view` or `--routine`.
- `tpl render --context` refuses a document of another `schema_version` with
  `65`.
- A backslash-newline in a `password_command` string is a line continuation, as
  in POSIX.

## Migration from v0.0.1

1. **Rename the lookup calls in your templates.**

   ```jinja
   {# v0.0.1 #}
   {% set t = table("customer") %}

   {# v0.0.2 #}
   {% set t = table_named("customer") %}
   ```

   Replace `view(...)` with `view_named(...)` and `routine(...)` with
   `routine_named(...)` in the same way. `tpl template check` does not detect an
   old name, because the call fails only when a render reaches it; search the
   templates instead:

   ```sh
   grep -rnE '\b(table|view|routine)\(' .tpl/templates/
   ```
2. **Replace a `.tpl/.cfg` symbolic link with a regular file.** A linked `.cfg`
   was read at its target in v0.0.1 and is refused with `78` in v0.0.2. Replace
   it with a regular file, or keep the project elsewhere and name its `.tpl`
   folder with `--tpl-dir`.
3. **Point `core.database` at an existing entry.** `tpl cfg set core.database`
   now refuses a name that no entry in `.tpl/.cfg` declares. Add the entry with
   `tpl cfg database add` first.

## Installation

```sh
curl -fsSL https://raw.githubusercontent.com/FlavioCFOliveira/tpl/main/install.sh | sh
```

The same command installs and updates `tpl`, into `/usr/local/bin` by default,
or into the directory `TPL_INSTALL_DIR` names. To install or update the Claude
Code skill:

```sh
curl -fsSL https://raw.githubusercontent.com/FlavioCFOliveira/tpl/main/install-skill.sh | sh
```

The release carries one archive per supported target
(`x86_64-unknown-linux-musl`, `aarch64-unknown-linux-musl`,
`x86_64-apple-darwin`, `aarch64-apple-darwin`), the skill archive
`tpl-skill-v0.0.2.tar.gz`, and one `SHA256SUMS` file covering all five
archives. **The archives are not signed.**

## Test evidence

The mandatory validation pipeline was run locally on the release candidate:
`release/0.0.2` at `dd11ac0` with the version bumped to `0.0.2`.

| Command | Result |
|---|---|
| `cargo fmt --all -- --check` | exit 0 |
| `cargo clippy --all-targets --all-features -- -D warnings` | exit 0, no warnings |
| `cargo build --release` | exit 0; the binary prints `tpl 0.0.2` |
| `cargo test --all-features` | exit 0: 1 390 passed, 0 failed, 13 ignored |
| `cargo audit` | exit 0: 182 dependencies scanned, no advisory reported |

The 1 390 tests are 1 049 unit tests, 339 integration tests in 14 suites, and 2
doc-tests.

- **Database tests skipped.** The MariaDB fixture was not running, so 121 tests
  that need a real server skipped themselves and are counted in the passed
  total.
- **Measurement tests ignored.** 13 tests are marked `#[ignore]` because they
  depend on wall-clock timing or on memory sampling. `cargo test` does not run
  them.
- **Environment:** `aarch64-apple-darwin`, macOS 26.6.2, rustc 1.98.1.
- **At the tag:** the release workflow re-runs the same five commands on all four
  supported targets before it publishes anything.
