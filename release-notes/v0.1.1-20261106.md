# tpl v0.1.1 — help and skill state each provider's behaviour

- **Version:** 0.1.1
- **Date:** 2026-11-06
- **Tag:** `v0.1.1`

`tpl` reads the schema of a MariaDB or MySQL database or a SQLite database file
and renders it through MiniJinja templates loaded from disk at render time.
v0.1.0 added the SQLite and MySQL providers, but some help text and some
statements of the Claude Code skill still described a MariaDB server alone.
This patch release corrects both. It changes no command, flag, exit code,
document key, configuration key or template name.

## Highlights

- **The help states what each command reads, for every provider.** The text
  help and `tpl help --format json` say whether a command reads no database,
  always reads it, or reads it only on a cache miss. They also say that a read
  connects to the server of a `mariadb` or `mysql` entry, or opens the file of
  a `sqlite` entry. No help text speaks of a server for a fact that also holds
  for a `sqlite` entry.
- **The Claude Code skill states each provider's behaviour correctly.** The
  skill in `tpl-skill-v0.1.1.tar.gz` corrects facts that v0.1.0 gave for
  MariaDB alone.

## Changes by area

The full list is the `0.1.1` entry of
[`CHANGELOG.md`](https://github.com/FlavioCFOliveira/tpl/blob/v0.1.1/CHANGELOG.md).

### Changed

- **Help text.** In the text help and the JSON command tree, the first sentence
  about side effects of every command has one of three provider-neutral forms:
  *Reads no database.*, *Always reads the database.*, or *Reads the database only
  when … .tpl/.cache/ does not already hold the data*. Each command that reads
  the database adds one sentence saying what a read is for each provider.
  Other help strings that spoke only of a server now name both cases, such as
  "another server or another database file". The exit `69` and `74` lines of
  `tpl cache load` now name the same SQLite outcomes as the `schema`
  subcommands.

### Fixed

- **Skill: login that needs the server's RSA public key.** Over an unencrypted
  session, such a login exits `78` for a `mysql` entry and `69` for a `mariadb`
  entry. The v0.1.0 skill gave `78` for both.
- **Skill: the `quote` filter.** It writes MariaDB backticks whatever the
  provider.
- **Skill: the read-only guarantee.** The skill now lists the closed set of
  statements a read issues for each provider.
- **Skill: SQLite write-ahead-log files.** A `--direct --no-cache` read may
  leave `-wal` and `-shm` files beside a SQLite database in write-ahead-log
  mode.
- **Skill: the model.** The skill lists the model values that differ between
  MariaDB, MySQL and SQLite, and the check-constraint and trigger fields.

### Internal

- The functional specification moves to its 88th edition, which fixes the
  provider-neutral help sentences in `FR-HELP-031` and `FR-HELP-038`.
- `tests/help_surface.rs` asserts the new help strings.

## Upgrade notes

No action is required. A script or agent that matches help text word for word
should be checked against the new sentences; the exit codes, the JSON documents
and the configuration are unchanged. To update the skill, run the installer
below again.

## Installation

```sh
curl -fsSL https://raw.githubusercontent.com/FlavioCFOliveira/tpl/main/install.sh | sh
```

The same command installs and updates `tpl`, into `/usr/local/bin` by default,
or into the directory `TPL_INSTALL_DIR` names. To install or update the Claude
Code skill:

```sh
curl -fsSL https://raw.githubusercontent.com/FlavioCFOliveira/tpl/main/install-skill.sh | sh
```

The release carries one archive per supported target
(`x86_64-unknown-linux-musl`, `aarch64-unknown-linux-musl`,
`x86_64-apple-darwin`, `aarch64-apple-darwin`), the skill archive
`tpl-skill-v0.1.1.tar.gz`, and one `SHA256SUMS` file covering all five
archives. **The archives are not signed.**

## Test evidence

The mandatory validation pipeline was run locally on the release candidate:
`develop` at `51f40c2` with the version bumped to `0.1.1`.

| Command | Result |
|---|---|
| `cargo fmt --all -- --check` | exit 0 |
| `cargo clippy --all-targets --all-features -- -D warnings` | exit 0, no warning in `tpl` |
| `cargo build --release` | exit 0; the binary prints `tpl 0.1.1` |
| `cargo test --all-features --no-fail-fast` | exit 0: 1 682 passed, 0 failed, 13 ignored |
| `cargo audit` | exit 0: 154 dependencies scanned, no advisory reported |

The 1 682 tests are 1 246 unit tests, 434 integration tests in 20 suites, and
2 doc-tests.

- **Database fixtures running.** The MariaDB fixture (series 10.11, 11.4, 11.8
  and 12.3, and a server without TLS) and the MySQL fixture (series 8.4 and 9.7,
  each with and without TLS, and an 8.0 server for the refused-series case) were
  started and stopped through their harnesses, so the tests that need a real
  server ran against them.
- **Assertions skipped on this target.** 2 tests skipped their assertion and are
  counted in the passed total: both observe a syscall trace that exists only on
  the two Linux targets.
- **Measurement tests ignored.** 13 tests are marked `#[ignore]` because they
  depend on wall-clock timing or on memory sampling. `cargo test` does not run
  them.
- **Environment:** `aarch64-apple-darwin`, macOS 27.2, rustc 1.99.1.
- **At the tag:** the release workflow re-runs the same five commands on all
  four supported targets before it publishes anything.
