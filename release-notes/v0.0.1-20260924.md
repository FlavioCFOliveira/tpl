# tpl v0.0.1 — first release

- **Version:** 0.0.1
- **Date:** 2026-09-24
- **Tag:** `v0.0.1`

`tpl` is a command-line tool that reads the schema of a MariaDB database from
`INFORMATION_SCHEMA` and renders it through MiniJinja templates, loaded from disk
at render time, to produce text or source code. It is read-only over the
database, and its help text, exit codes and output are designed as a contract
for AI coding agents.

This is the first release. It contains everything built since the first commit.

## Highlights

- **The complete command tree.** `schema`, `template`, `render`, `cache`, `cfg`,
  `init`, `help` and `version`: 34 nodes, 29 of them invocable, each with help.
- **Read-only catalogue reading.** One connection per invocation, a read-only
  session enforced before any statement, and a fixed repertoire of eleven
  `INFORMATION_SCHEMA` statements. `tpl` never writes to the database.
- **Runtime rendering.** `tpl render` renders one MiniJinja template against the
  catalogue or a `--context` document, bounded by a deadline, render fuel, an
  output limit and a memory limit.
- **A machine-readable surface.** `tpl help --format json` publishes the command
  tree, the global flags, the context variables and the twenty-three registered
  template names in one document.
- **A catalogue cache.** A later read of the same database entry is served from
  `.tpl/.cache/` and opens no connection.

## What is included

The full list is the `0.0.1` entry of
[`CHANGELOG.md`](https://github.com/FlavioCFOliveira/tpl/blob/v0.0.1/CHANGELOG.md).
By area:

- **Command line:** eight subcommands, short aliases, seven global flags
  accepted in any position.
- **Projects and configuration:** `tpl init`, upward discovery of the `.tpl`
  folder, `--tpl-dir`, and `cfg get`/`set`/`unset`/`list` and `cfg database`,
  which preserve the comments and ordering of `.tpl/.cfg`. Credentials can come
  from a `password_command` helper, bounded in time and output.
- **Connection testing:** `cfg database test` reports connection, read-only
  session, server series and catalogue privileges.
- **Schema exploration:** `schema info`, `tables`, `table`, `views`, `view`,
  `routines`, `routine` and `dump`. What the reader's privileges did not reach is
  marked in the model rather than omitted.
- **Cache:** `cache load`, `cache clean` and `cache status`; `--no-cache` and
  `--direct` bypass it.
- **Templates:** `template list`, `show`, `check` and `path`.
- **Render environment:** eleven filters, seven tests and five functions,
  guaranteed by `tpl` as a contract.
- **Output and diagnostics:** one JSON envelope (`schema_version`, `source`,
  `data`), `sysexits` exit codes, nearest-match suggestions, and error messages
  that state what failed, why, and a command that can succeed.
- **Examples:** four worked examples in `examples/` that generate a data layer in
  Go, Rust, Python and Node.js and compile the result.
- **Distribution:** `install.sh` and one archive per supported target with a
  `SHA256SUMS` file.

## Breaking changes and migration

None. There is no earlier release to migrate from.

While `tpl` is below 1.0, a breaking change increments the minor version.

## Installation

```sh
curl -fsSL https://raw.githubusercontent.com/FlavioCFOliveira/tpl/main/install.sh | sh
```

The same command installs and updates `tpl`, into `/usr/local/bin` by default,
or into the directory `TPL_INSTALL_DIR` names. It verifies the archive against
the release's `SHA256SUMS` before installing.

Supported targets: `x86_64-unknown-linux-musl`, `aarch64-unknown-linux-musl`,
`x86_64-apple-darwin` and `aarch64-apple-darwin`. Windows is not supported.

## Known limitations

- **The archives are not signed.** `SHA256SUMS` proves that an archive matches
  the release, not who produced it.
- **Supported MariaDB series** are defined in
  [`specification/server-contract.md`](https://github.com/FlavioCFOliveira/tpl/blob/v0.0.1/specification/server-contract.md).

## Test evidence

The mandatory validation pipeline was run locally on the release candidate:
`release/0.0.1` at `49b1e2f` with the version bumped to `0.0.1`.

| Command | Result |
|---|---|
| `cargo fmt --all -- --check` | exit 0 |
| `cargo clippy --all-targets --all-features -- -D warnings` | exit 0, no warnings |
| `cargo build --release` | exit 0; the binary prints `tpl 0.0.1` |
| `cargo test --all-features` | exit 0: 1 353 passed, 0 failed, 0 ignored |
| `cargo audit` | exit 0: 182 dependencies scanned, no advisory reported |

The 1 353 tests are 1 051 unit tests, 300 integration tests in 9 suites, and 2
doc-tests.

**Database tests were skipped.** The MariaDB fixture was not running, so 122
tests that need a real server skipped themselves and are counted in the passed
total above. Continuous integration also runs without the fixture.

- **Environment:** `aarch64-apple-darwin`, macOS 26.6.2, rustc 1.98.1.
- **At the tag:** the release workflow re-runs the same five commands on all four
  supported targets before it publishes anything.
- **Fixture fix before release:** `49b1e2f` corrects the test fixture script
  `scripts/mariadb/observe.sh`, which mixed the host `strace` trace with the
  traced command's stdout and made an `NFR-PERF-007` test fail on Linux CI. It
  changes no behaviour of `tpl`. The local run above is on macOS and does not
  exercise that path; the Linux targets at the tag do.
