# tpl v0.1.3 — one meaning of connection across the documentation

- **Version:** 0.1.3
- **Date:** 2026-11-06
- **Tag:** `v0.1.3`

`tpl` reads the schema of a MariaDB or MySQL database or a SQLite database file
and renders it through MiniJinja templates loaded from disk at render time.
Until now, its documentation used "connection" both for a session with a
MariaDB or MySQL server and for opening a SQLite database file. This patch
release gives the word one meaning — a MariaDB or MySQL server — across the
specification, the technical specification, the README and the code comments.
It changes no behaviour, help text, message, exit code, command, flag, document
key, configuration key or template name.

## Highlights

- **"Connection" names a MariaDB or MySQL server only.** A SQLite read opens
  the database file; the documentation now says so wherever it described a
  SQLite read as a connection.
- **The traceability is complete through the 90th edition.** Every requirement
  of the functional specification maps to the technical specification.

## Changes by area

The [`CHANGELOG.md`](https://github.com/FlavioCFOliveira/tpl/blob/v0.1.3/CHANGELOG.md)
entry for `0.1.3` records no caller-visible change.

### Documentation

- **README.** `tpl cfg database test` is described as the one `cfg`
  subcommand that reads a database: it connects to the server of a MariaDB or
  MySQL entry, or opens the database file of a SQLite entry. A read served from
  the catalogue cache does not read the database, and `tpl render` closes what
  the read opened — the connection or the database file — before the template
  starts.

### Internal

- The functional specification moves to its 90th edition. The glossary narrows
  "connection" to a MariaDB or MySQL server and adds opening the database file
  for SQLite; requirements that used "connection" for every provider are
  reworded to keep their SQLite half.
- The technical specification uses "connection" with the same meaning, and its
  traceability maps editions 85 to 90: 1 001 of 1 001 requirements.
- Code comments use "connection" for a server only. No code line changed.

## Upgrade notes

No action is required. The binary behaves exactly as v0.1.2: the exit codes,
the help, the messages, the JSON documents and the configuration are
unchanged. The Claude Code skill is unchanged since v0.1.1.

## Installation

```sh
curl -fsSL https://raw.githubusercontent.com/FlavioCFOliveira/tpl/main/install.sh | sh
```

The same command installs and updates `tpl`, into `/usr/local/bin` by default,
or into the directory `TPL_INSTALL_DIR` names. To install or update the Claude
Code skill:

```sh
curl -fsSL https://raw.githubusercontent.com/FlavioCFOliveira/tpl/main/install-skill.sh | sh
```

The release carries one archive per supported target
(`x86_64-unknown-linux-musl`, `aarch64-unknown-linux-musl`,
`x86_64-apple-darwin`, `aarch64-apple-darwin`), the skill archive
`tpl-skill-v0.1.3.tar.gz`, and one `SHA256SUMS` file covering all five
archives. **The archives are not signed.**

## Test evidence

The mandatory validation pipeline was run locally on the release candidate:
`develop` at `88de7a8` with the version bumped to `0.1.3`.

| Command | Result |
|---|---|
| `cargo fmt --all -- --check` | exit 0 |
| `cargo clippy --all-targets --all-features -- -D warnings` | exit 0, no warning in `tpl` |
| `cargo build --release` | exit 0; the binary prints `tpl 0.1.3` |
| `cargo test --all-features --no-fail-fast` | exit 0: 1 686 passed, 0 failed, 13 ignored |
| `cargo audit` | exit 0: 154 dependencies scanned, no advisory reported |

The 1 686 tests are 1 249 unit tests, 435 integration tests in 20 suites, and
2 doc-tests.

- **Database fixtures running.** The MariaDB fixture (series 10.11, 11.4, 11.8
  and 12.3, and a server without TLS) and the MySQL fixture (series 8.4 and 9.7,
  each with and without TLS, and an 8.0 server for the refused-series case) were
  started and stopped through their harnesses, so the tests that need a real
  server ran against them.
- **Assertions skipped on this target.** 2 tests skipped their assertion and are
  counted in the passed total: both observe a syscall trace that exists only on
  the two Linux targets.
- **Measurement tests ignored.** 13 tests are marked `#[ignore]` because they
  depend on wall-clock timing or on memory sampling. `cargo test` does not run
  them.
- **Environment:** `aarch64-apple-darwin`, macOS 27.2, rustc 1.99.1.
- **At the tag:** the release workflow re-runs the same five commands on all
  four supported targets before it publishes anything.
